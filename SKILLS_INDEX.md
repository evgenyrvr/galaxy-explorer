# Galaxy Explorer — набор скиллов для разработки

**Статус:** спецификации навыков для будущего AI-исполнителя / команды, **не исполняемый код**.  
**Связанное ТЗ:** [TECHNICAL_SPECIFICATION.md](TECHNICAL_SPECIFICATION.md)

Каждый навык оформлен отдельным файлом `skills/<name>/SKILL.md` с назначением, входными данными, рабочей последовательностью, артефактами, правилами и критериями готовности. Такая структура позволяет поручать отдельные части работы разным агентам и проверять результат по единым условиям.

## Очерёдность использования

1. **01 → 02 → 03.** Сначала согласовать требования и онтологию, затем реализовать непротиворечивый массовый бюджет. До этого не стоит строить сцену, иначе станет невозможно достоверно подсчитывать выделенные массы.
2. **04 → 05 → 06/07.** Раздельно готовятся генерация структур, 3D-отображение и взаимодействие с интерфейсом/Go.
3. **09 работает поперёк всех этапов.** У каждого объекта должен быть тип научного происхождения, даже если все первые пресеты синтетические.
4. **11 контролирует каждый релиз.** Основные автотесты — сумма 100%, отсутствие двойного счёта, смена слоёв без изменения физических масс и честная подпись источников.
5. **08 → 10, затем 12.** Наблюдательные данные, кинематика, упакованная программа.

## Единые правила всех скиллов

- Источник истины по функциям и приёмке — `TECHNICAL_SPECIFICATION.md`.
- В расчётах исходить из физических масс, а **не** из количества или яркости нарисованных точек.
- Для одного объекта допускаются несколько структурных меток, но только один учёт массы.
- В интерфейсе отделять **галочку видимости**, **выделение**, **материальный фильтр** и **вклад в суммарную массу**.
- Не генерировать «наблюдательные» координаты или ошибки при отсутствии измерений.
- Соблюдать физические единицы и области применимости: `M☉`, `кпк`, `M☉/пк²`, `M☉/пк³`, `км/с`.
- Чёрная дыра и тёмная материя не должны подаваться как обычные светящиеся структуры; способ отображения условный.
- Каждая задача должна завершаться воспроизводимым результатом, тестами и коротким changelog.

## Определение готовности набора навыков

Навыки описаны настолько подробно, чтобы отдельный разработчик или агент мог составить план реализации, определить входные и выходные данные, не нарушить физические ограничения и проверить сдаваемую функцию по приёмочным тестам. **Исполняемая программа и код в этот комплект не входят.**
